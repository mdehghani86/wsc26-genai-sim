Companion application

A tutorial on Generative AI and Simulation Modeling Integration

A live, in-browser walk-through of the four-phase GenAI-driven simulation workflow. Each tab on the left maps to one phase of the paper, and each phase consumes the artefact produced by the previous one. There is no backend: every Python cell on this site runs in your browser via Pyodide.

Phase 0
Problem formulation
A structured prompt that returns a three-row schema: problem, scope, KPIs. The artefact every later phase is judged against.
Phase 1a · live
Input modelling
Upload arrival data or pick a demo trace. The LLM proposes candidate distributions; scipy runs the chi-square, KS, and Anderson-Darling tests; the test wins.
Phase 1b
Model creation
From the Phase 0 schema and the Phase 1a fitted distribution, generate a runnable SimPy model. Compare vibe-coding, multi-agent, and MCP paths.
Phase 2
Execution
Run the simulation, narrate the trace in plain English, and surface the events that matter for the Phase 0 problem statement.
Phase 3
Experimentation
Scenario sweeps and results interpretation, scored against the Phase 0 KPI list.
Extension
Agentic AI via MCP
An LLM constructs the simulation by calling typed tools (define_resource, define_process, run, query_kpis) over the Model Context Protocol.
Connectivity spine
Phase 0 → Phase 1a → Phase 1b → Phase 2 → Phase 3. Every page tells you which artefact it consumed and which artefact it produces.
Reproducibility
Source: github.com/mdehghani86/wsc2025-genai-simulation-tutorial. Every prompt and every script on this page is in the repo.
Phase 0

Problem formulation

Phase 0 produces no code. It produces a written agreement on three items: the problem to be solved, the scope and boundaries of the system under study, and the key performance indicators (KPIs) the simulation will be judged against. Every later tab consumes this schema unchanged.

Prompt

I am planning a discrete-event simulation of an emergency department. Help me formulate the study as a structured problem statement.

Notes small community hospital, two triage tiers, the team wants to evaluate staffing and routing rule changes.

Search recent literature (2023–2025) on emergency-department simulation studies and pull common KPIs.

Return a single table with three rows: Problem definition, Scope & boundaries, and KPIs. Keep each cell to two or three short sentences.

Response
ElementStatement
1Problem definition Reduce length of stay in the emergency department and identify whether triage-rule changes or staffing changes deliver the larger improvement under fluctuating arrival rates.
2Scope & boundaries From walk-in arrival to admit-or-discharge. Two triage tiers (urgent, non-urgent), a shared imaging and laboratory pool, and fixed bed pools. Ambulance routing, no-shows, and inpatient bed flow are out of scope.
3KPIs Mean and 95th-percentile length of stay; door-to-doctor time per triage tier; bed and imaging utilisation; daily throughput.
This produces
A three-row schema. Row 2 (scope) feeds Model creation. Row 3 (KPIs) feeds Experimentation. Row 1 (problem) anchors the Execution narration.
